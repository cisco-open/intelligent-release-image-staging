IRIS

IRIS gets large Cisco images and patches onto routers and switches faster by letting devices share downloaded pieces with each other. Each device verifies what it receives and stops at staging.

How it works

The simple idea: devices help each other download.

With a normal file server, every device asks the server for the whole image. With IRIS, the server introduces the image and devices exchange the pieces they already have. The more devices participate, the more download capacity the fleet can contribute.

Devices fetch missing pieces from the server and from peers. Transfers resume, load spreads out, and each device verifies the final staged image.

01

Faster fleet distribution

The server no longer has to send every byte of a multi-gigabyte image to every device. Devices that have pieces can help other devices catch up.

02

Better fault tolerance

BitTorrent-style piece transfers can resume after interruption, and devices can fill missing pieces from more than one source once the swarm has content.

03

Safer change control

IRIS only stages the approved image. Install, activation, boot changes, and reloads stay outside the tool and under operator control. On an existing management VLAN (inband), IRIS also never creates, changes, or removes that VLAN, its SVI, gateway, routes, or VRF. Management type and VLAN ownership.

Workflow

Publish, assign, stage, stop.

Run it your way. Every step below shows the command line — and every one is equally a few clicks in the IRIS Console: publish an image, choose who gets it, and watch the fleet stage in real time. Script it into your automation or drive it from the browser; the guarantees never change — swarm delivery, verification on the device, and a hard stop before activation.

Publish an image

The operator publishes one Cisco image or patch. IRIS records the hashes and creates private swarm metadata for the fleet.

iris-publish /opt/images/<image>.bin

Catalyst 9000 Guest Shell

Platforms

Same delivery model, platform-specific staging.

Catalyst 9000 switches run the agent in Guest Shell, or as an IOx app where app-hosting storage is available. Industrial Ethernet platforms run the IOx app. Catalyst 8000 routers run Guest Shell through a VirtualPortGroup, in routed or NAT attachment. Every platform stages to its own device storage. Router preflight repeats before token mint, receipts bind management IP and processor-board identity, and router adoption requires re-onboarding. Visibility is built in, not bolted on: every transfer is live on the Swarm Map, and open OpenTelemetry export streams the same signals into Cisco Splunk in the reference deployment — or any OTLP destination you choose. Every path downloads by swarm, verifies on the device, and stops before activation.
