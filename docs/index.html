How it works

The simple idea: devices help each other download.

With a normal file server, every device asks the server for the whole image. With IRIS, the server introduces the image and devices exchange the pieces they already have. The more devices participate, the more download capacity the fleet can contribute.

Traditional pull

Every device pulls the whole image from one place. A large rollout waits on the server and its uplink.

IRIS private swarm

The server seeds each image once. Devices take missing pieces from the server and from each other, resume after an interruption, and verify the image before staging it. Peer transfers run over TLS with mutual certificates when you turn that on.

01

Peer-assisted distribution

Reachable, eligible peers can supply image pieces and reduce server traffic. Results depend on the network and swarm.

02

Better fault tolerance

BitTorrent-style piece transfers can resume after interruption, and devices can fill missing pieces from more than one source once the swarm has content.

03

Safer change control

IRIS only stages the approved image. Install, activation, boot changes, and reloads stay outside the tool and under operator control. On an existing management VLAN (inband), IRIS also never creates, changes, or removes that VLAN, its SVI, gateway, routes, or VRF.

Workflow

Publish, assign, stage, stop.

Platforms

One agent across device platforms.

IOx and IOS-XR appmgr use one device-agent container build for arm64 and amd64. Each platform has its own package and storage handling. Guest Shell runs the same agent code from a bundle.

Device families include Catalyst, Industrial Ethernet, Cisco 8000, and NCS. Available deployment paths depend on device capabilities and software.

The server and web Console run in separate containers on one Docker host, separate Docker hosts, or Kubernetes. The server manages images, assignments, and the swarm; the Console provides the browser interface. Follow device staging and peer transfers in the Swarm Map, or export telemetry to an OpenTelemetry collector.

The Console, catalog, tracker, artifact server, telemetry listener, and internal management API use HTTPS. Device agents verify the server certificate. Image pieces travel through the private BitTorrent swarm. An operator can turn on TLS with mutual certificates for peer transfers between devices; that setting is off by default.
