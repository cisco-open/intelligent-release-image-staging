IRIS

IRIS gets large Cisco images and patches onto routers and switches faster by letting devices share downloaded pieces with each other. Each device verifies what it receives and stops at staging.

How it works

The simple idea: devices help each other download.

With a normal file server, every device asks the server for the whole image. With IRIS, the server introduces the image and devices exchange the pieces they already have. The more devices participate, the more download capacity the fleet can contribute.

Devices fetch missing pieces from the server and from peers. Transfers can resume after interruption. Each agent verifies and stages the image before reporting it ready.

01

Faster fleet distribution

Devices share image pieces with peers, reducing how much each device needs to download from the server.

02

Better fault tolerance

BitTorrent-style piece transfers can resume after interruption, and devices can fill missing pieces from more than one source once the swarm has content.

03

Safer change control

IRIS only stages the approved image. Install, activation, boot changes, and reloads stay outside the tool and under operator control. On an existing management VLAN (inband), IRIS also never creates, changes, or removes that VLAN, its SVI, gateway, routes, or VRF. Management type and VLAN ownership.

Workflow

Publish, assign, stage, stop.

Use the Console or command line to publish an image, assign it to devices, and follow staging progress. IRIS stages the image without changing the device's running software.

Publish an image

The operator publishes one Cisco image or patch. IRIS records the hashes and creates private swarm metadata for the fleet.

iris-publish /opt/images/<image>.bin

Platforms

One agent across device platforms.

IOx and IOS-XR appmgr use one device-agent container build for arm64 and amd64. Each platform has its own package and storage handling. Guest Shell runs the same agent code from a bundle.

The server and web Console run in separate containers on one Docker host, separate Docker hosts, or Kubernetes. The server manages images, assignments, and the swarm; the Console provides the browser interface. Follow device staging and peer transfers in the Swarm Map, or export telemetry to an OpenTelemetry collector.

The Console, catalog, tracker, artifact server, telemetry listener, and internal management API use HTTPS. Device agents verify the server certificate. Image pieces travel through the private BitTorrent swarm. See network ports and flows for firewall requirements.
