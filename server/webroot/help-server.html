Server-side setup & troubleshooting

First run

Before an admin account exists, use the first-run credential documented in the operator manual. It works only pre-setup and takes you straight to the wizard that creates the real admin account. The moment an admin exists it loses its special first-run status and is checked only against the stored administrator account. The CLI alternative from the server host is:

docker compose -f server/docker-compose.yml exec iris iris-gui-admin admin

Recovery checklist

  1. Confirm docker ps shows the iris container, then read docker logs iris for catalog, tracker, seeder, or secretfs errors.
  2. Confirm devices can reach ports 8443 (catalog), 8000 (artifacts), 6969 (HTTPS tracker), and 6881 (seeder); operators need 8080 (this console).
  3. Check host-path ownership: every service runs at uid 10001. An image listed as not readable by the server, a secrets store that suddenly fails to decrypt, or an agent-bundle download failure after a reset is an ownership problem, not corrupt state — re-chown the age key, the artifacts directory, and every kept volume to 10001:10001.
  4. Check the audit trail (Monitoring → Audit trail) for the last admin or workflow action before the symptom started.
  5. Check service health: HTTPS /healthz on port 9101 answers only a minimal {"ok":true} probe body.

Device packages and certificate changes

The IOx tars (iris-arm64.tar / iris-amd64.tar) and iris-xr.rpm contain agent code but no deployment certificate. Onboarding supplies the current public certificate separately. After certificate rotation, re-onboard affected devices; the existing packages can be reused. Agent source changes require rebuilding every package: run tools/provision-iox-packages.sh for IOx and tools/build-xr-package.sh --out artifacts/ for IOS-XR from the repository root. The Console's Settings → Device packages page reports all three artifacts and can re-check their bytes against build provenance, but builds must run on the Docker host. A ready result does not validate a native signature; signed packages must remain immutable.

Where state lives

  • /etc/iris — encrypted secrets, generated TLS material, and the audit trail (audit.jsonl).
  • /var/lib/iris — catalog state, policies, torrent metadata, deployment records, deploy logs.
  • /run/iris — plaintext runtime secrets, tmpfs only: gone on restart by design, rebuilt from the encrypted store.
  • /var/lib/iris-images — console-uploaded images. Back this volume up too; a restore without it loses the uploads.
