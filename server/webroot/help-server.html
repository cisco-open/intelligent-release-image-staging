Server-side setup & troubleshooting

First run

Open the Console on HTTPS port 8080, or the port set by IRIS_GUI_PUBLISH. Before an administrator exists, the documented first-run login opens account setup. Complete setup from a trusted management network. To create or reset the administrator from the server host, run:

docker compose -f server/docker-compose.yml exec iris iris-gui-admin admin

Server and Console

The stack has two services: iris owns the catalog, tracker, seeder, artifacts, credentials, and device jobs; console serves the browser interface. Their default container names are iris and iris-console. The Console forwards browser /api/v1 requests to https://iris:9443/internal/v1 using a mounted service credential and the management CA.

Docker assigns private addresses on the Compose network. The service name iris resolves there. On separate Docker hosts, the Console calls the server's private address through IRIS_MANAGEMENT_API_URL. Neither container needs a separate LAN address. Devices use the server host's published ports; operators use the Console host's address.

  • Devices reach HTTPS 8443 (catalog), 8000 (install artifacts), and 6969 (tracker), plus TCP 6881 for image pieces.
  • Operators reach Console HTTPS 8080. Compose binds this port on IRIS_HOST_IP in the one-host stack, or IRIS_CONSOLE_BIND_IP in the standalone Console deployment.
  • HTTPS 9101 serves probes and authenticated telemetry. The swarm map is in the Console, not on this port.
  • Management HTTPS 9443 uses the Compose network or a private server-host binding restricted to the Console host. Seeder RPC 6800 stays on server loopback.

Installer command failures

A failed managed build names a private diagnostics file in the terminal error. Inspect it locally as root and keep the installation state for resume. The installer retains at most eight files, each with the last 128 KiB of stdout and stderr. Earlier logs are never overwritten. These files can contain credentials: do not share them in tickets, chat or public logs. See Installer command failures.

Settings saves

In General, TLS & trust, Telemetry and Audit export, an uncertain save requires Reload current settings and review before retrying. Sign in again after an uncertain password change. Submitted passwords and private keys clear from their forms, as they do when you leave the section or hide the tab. Leaving a page does not cancel a submitted request.

Importing a browser certificate reloads only the Console that handled the request. If it was saved but reload was not confirmed, restart that Console. Restart other Console instances too, then verify the served certificate on a new trusted connection to each instance.

Local API reference

Open the local Swagger API reference from Help → Local API reference, on this Console's HTTPS address and port. Its assets and canonical OpenAPI contract are bundled with the Console and load without Internet access. Browsing the public contract does not require a session; sending API requests still requires the documented authentication. The reference is read-only.

If /swagger/ returns 404, confirm that you are using the Console's published port and an updated Console image. The server's management and device-facing ports do not serve this page. Preserve the trailing slash, or use /swagger/index.html, so asset links resolve correctly. The page identifies limitations in Swagger's schema renderer; its canonical explorer and raw contract contain the exact schemas and streaming examples.

Recovery checklist

Run these commands from the repository root to check both services:

docker compose -f server/docker-compose.yml ps
docker compose -f server/docker-compose.yml logs --tail=100 iris console

For separate hosts, use server/docker-compose.server.yml on the server and server/docker-compose.console.yml on the Console host, together with each host's --env-file. The separate-host setup guide covers certificates, credentials, and commands.

  1. If the Console cannot load, check the console logs, its published port, and the browser certificate. The one-host Compose stack fetches that identity from the server. The standalone Console uses its local certificate and can start while the server is unavailable.
  2. If the page loads but API requests return 503, check iris health and logs, the private network, and the Console's management URL, private DNS or routing, firewall on 9443, and read-only tier-token and management-CA mounts. Confirm the management certificate covers the hostname or IP in the URL. A browser certificate and the management CA serve different connections.
  3. If the response code is projection-busy, a device-status read waited too long behind another read. Retry after Retry-After; repeated failures call for checking server load and storage health.
  4. Use /readyz for readiness: on server port 9101 it checks the tracker, catalog, artifact, and management listeners. /healthz only proves the telemetry process answers. Console probes on 8080 check the Console itself; they do not prove the server is available.
  5. For permission errors, confirm uid 10001 can read the age identity and host image tree, and can write artifacts and server volumes. Keep the age identity mode 600 or 400. A decryption error can also mean the wrong identity or damaged ciphertext; check the reported cause before changing state.
  6. Check Monitoring → Audit trail for the last settings or device action, and the device job log for onboarding or undeploy failures.
  7. In Manage credentials, Refresh profiles checks an unavailable list. An unknown save or delete result means the response was lost or incomplete; refresh and check before trying again. Closing the panel or leaving the tab clears entered passwords, but does not cancel a submitted save.
  8. If Inventory shows unavailable credentials or sharing policy, check the server connection before editing those fields. An unknown edit outcome means the response was lost or unreadable; check the refreshed row before trying again.
  9. Image and bulk credential dialogs keep the devices you reviewed when you opened them. Check reviewed devices before applying. For an image conflict or unknown result, choose Review current assignments and check the new selection before applying again. Closing a dialog does not cancel submitted changes.
  10. Add device checks the model series and management type together before offering an agent install. Catalyst 8000 series uses Router routed or Router NAT for Guest Shell or IOx. Reopen the form if the compatibility check is unavailable.
  11. Forget host key confirms the selected device's saved SSH entry is absent, including hashed entries, and preserves other devices' keys. Verify a replaced device's identity before using this action.
  12. CSV import results stay below the Inventory toolbar. Device edits wait until an import finishes. If its response is uncertain, check Inventory before retrying.
  13. Delete reports incomplete cleanup separately from a completed retirement. Partial or unknown targets stay selected, even if their rows have left Inventory. Read the named cleanup steps and audit trail before retrying.
  14. Schedule dialogs keep the filter and selected devices reviewed at opening. Check Reviewed target before creating a window. An unknown creation result needs Refresh schedules before retrying; check whether the named schedule already exists. Closing the dialog does not cancel a submitted request.
  15. Set role keeps its reviewed devices fixed. If the result is uncertain, use Refresh policy before retrying and check the roles before another preview. Bulk quarantine stops on an uncertain result; devices marked not attempted were left unchanged by that batch.
  16. A partial role change is not a rollback. Repair the reported store failure, refresh inventory and policy, and review applied, failed and drift results. Preview the remaining change with the current revision before confirming; an earlier confirmation can be refused.
  17. In Policies, preview a role definition before saving. An uncertain save needs a refresh and review; Reload current definition discards your draft. Role CSV exports include seeder and leecher timing overrides; blank or missing timing columns remove those overrides on import. The page loads when opened and after a save. Choose Refresh policies to check for changes from elsewhere.
  18. Under Speed limits and agent settings, expiry applies to the last verified settings message, not the saved role. Keep its verified transfer settings or use the device agent's built-in settings, which have no upload or download speed limit. Transfers can continue. This choice does not extend expired peer permissions or stop every existing connection.
  19. Policies → Distribution access starts in Preview only. To enforce reviewed restrictions, set the new-device and new-address limits, select Preview change, check the counts, then Apply reviewed change. Choose Refresh status to check current application, not just the requested mode. A shared allowed/denied address needs separate addresses. After an uncertain save, use Refresh status before another preview. Refreshing asks before discarding an unsaved draft or preview.

Device packages and certificate changes

In Settings → Certificates & keys, the overview shows what each certificate protects, its status and expiry. Open Renew signing certificate to extend validity with the same key. Technical details and advanced changes start closed. Open Advanced: replace signing key only when the key itself needs replacing. Automatic local setup keys use their saved passphrases for approval; you still review the request and return the public approval. Renewal is not automatic. Advanced: replace deployment keys covers connection and encryption keys. The browser certificate this Console serves, including its expiry, is in TLS & trust.

For an uncertain instruction certificate renewal, download a fresh public renewal request before submitting again. For an uncertain signer rotation, select Refresh rotation and review the request ID, fingerprints and state. Leaving the page clears selected approval files but does not cancel a submitted request.

For browser certificate replacement, Refresh request shows the current request and publication state. Check the apply result for listener reload, then verify a new trusted browser connection. For telemetry credentials, Refresh evidence shows replacement use; confirm every consumer before finishing. Unknown or refused results need an explicit refresh and review. Submitted or hidden forms clear entered credentials; returning to the page does not repeat a request.

For deployment rotation, use Refresh maintenance evidence after reconnecting. For backups, use Refresh backup history. Match the operation ID and check its result; acceptance is not completion. An uncertain response needs a refresh and review before another request. Running or interrupted worker operations block new maintenance.

Restore keeps your current Policies → Distribution access settings and safety records for shared IP addresses. Check application status again after the server restarts.

Scheduled key maintenance keeps your draft if saved settings change. Choose Reload saved schedule and review the UTC window before saving again. For an uncertain save, Refresh maintenance and check the saved schedule first. Returning to a page never resubmits work.

After a scheduled management credential replacement, open Inventory and verify every Console before selecting Retire previous credential.

IOx and IOS-XR use the same device-agent image, packaged as iris-arm64.tar, iris-amd64.tar, and iris-xr.rpm. Guest Shell receives the shared agent in a bundle. These packages are separate from the server and Console images.

The IOx tars and XR RPM contain no deployment certificate. Onboarding supplies it separately. After certificate rotation, re-onboard affected devices; the packages can be reused.

After shared-agent changes, rebuild the server to refresh the Guest Shell bundle, then rebuild both IOx packages and the XR RPM on the Docker host. See the package rebuild instructions. Settings → Device packages checks wrapper bytes against their build manifests. A ready result does not authenticate those manifests, prove the packages contain the latest source, or validate a native signature. Artifact updated is the file's modification time. Build only the platforms you use, then select Re-check packages.

Settings → Image verification shows completed Bulk Hash checks separately from a configured schedule. If a reply is lost, use Review current status before retrying. Review discards unsaved schedule edits and loads the latest evidence; it cannot prove the result of an earlier request.

Where state lives

  • /etc/iris — encrypted server secrets, public TLS certificates, and the plaintext audit trail (audit.jsonl).
  • /var/lib/iris — catalog state, policies, torrent metadata, deployment records, and job logs.
  • /run/iris — decrypted server secrets on tmpfs, rebuilt from the encrypted store after a restart.
  • /var/lib/iris-images — uploaded images; /opt/images — the read-only host import tree.
  • /srv/artifacts — served bundles, native packages, manifests, and temporary install assets.

The Console mounts none of that state. It mounts only the tier credential and public management CA read-only. The standalone deployment also mounts its own default browser certificate and key; the active TLS identity stays in tmpfs. Back up uploaded images as well as server state and encrypted configuration. Keep the age identity separately.
