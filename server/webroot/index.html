More filters
Use when a device is stranded — an onboard that died before its record was written, or a box that was rebuilt or replaced, so the record names hardware that is no longer there and the teardown refuses it on an identity mismatch. Force skips the record entirely and removes the IRIS agent footprint only: the VirtualPortGroup and NAT are left untouched, because nothing here proves IRIS created them. On an IOS-XR device, force removes the same IRIS-named footprint a normal undeploy would — the appmgr application iris, its iris-xr package source, the RPM, iris-work/, and the IRIS sidecar files at harddisk: root — but a staged image file there is never removed by IRIS teardown, and the agent deletes an adopted file only when the catalog republishes new content under that same image id — never otherwise. Any record for the device is abandoned once the teardown succeeds, so it can be onboarded again.

1. Telemetry destination 

              
Where swarm progress, device reports and export health
                are published. With no destination configured, none of it leaves this
                server.

              

            


            

              
2. Stage host 

              
Credentials IRIS uses to reach the Docker host that
                builds and serves device onboarding material. Without them, onboarding
                a device over the Docker path cannot start.

              

            


            

              
3. Device packages 

              
Devices that run the agent as an IOx app (IE-3x00, and
                C9300 with app-hosting) install a package that pins this server's
                certificate at build time. If that certificate changes, existing
                packages can no longer authenticate — the app installs and reports
                RUNNING, but the device never checks in. Guest Shell platforms re-fetch
                the certificate on every onboard and are not affected.

              
This step cannot be completed from the console.
                The console container has no Docker socket, so it can detect a stale
                package but never rebuild one. Run the command below on the Docker host,
                then re-check.

              

              

              

              

              

            


            

              
4. Image verification 

              
Confirms every staged image's hash against Cisco's
                Bulk Hash feed before it is trusted. Without at least one successful
                check, IRIS cannot vouch that a staged image is the genuine,
                untampered Cisco release.

Schedule

          
Cisco's Bulk Hash feed lists the sha512 of every
            genuine Cisco release image. A scheduled or manual check compares
            it against every image in this catalog and quarantines any that
            mismatch, blocking new device assignments until the mismatch is
            resolved or an operator explicitly overrides it.

Runs the check immediately against Cisco's live
            feed, outside the schedule above.
