              Undeploy devices 
              
            
        
            
        
              
        Removes the IRIS agent and record-owned resources from each selected device. Staged images at the filesystem root are left in place, and running jobs are never interrupted.
        
              
              
        
                Use when a device is stranded — an onboard that died before its
                record was written, or a box that was rebuilt or replaced, so the
                record names hardware that is no longer there and the teardown
                refuses it on an identity mismatch. Force skips the record
                entirely and removes the IRIS agent footprint only: the
                VirtualPortGroup and NAT are left untouched, because nothing here
                proves IRIS created them. On an IOS-XR device, force removes the
                same IRIS-named footprint a normal undeploy would — the appmgr
                application iris, its iris-xr package source, the RPM,
                iris-work/, and the IRIS sidecar files at harddisk: root — but a
                staged image file there is never removed by IRIS teardown, and
                the agent deletes an adopted file only when the catalog
                republishes new content under that same image id — never
                otherwise. Any record for the device is abandoned once the
                teardown succeeds, so it can be onboarded again.

        Admin account 
        
              
        Created during first-run sign-in. Change the password
                any time from Settings › General.
        
            
        

            
        
              
        1. Telemetry destination 
        
              
        Where swarm progress, device reports and export health
                are published. With no destination configured, none of it leaves this
                server.
        
              
        
            
        

            
        
              
        2. Device packages 
        
              
        IOx and IOS-XR devices install a deployment-neutral
                package. During onboarding IRIS separately copies this server's
                current certificate to the device. Certificate rotation requires
                re-onboarding affected devices, but does not require rebuilding
                their packages. Guest Shell keeps its existing onboarding flow.
        
              
        This step cannot be completed from the console.
                The console container has no Docker socket, so it can detect a stale
                package but never rebuild one. Run the command below on the Docker host,
                then re-check.
        
              
        
              
        
              
        
              
        
              
        
            
        

            
        
              
        3. Image verification 
        
              
        Confirms every staged image's hash against Cisco's
                Bulk Hash feed before it is trusted. Without at least one successful
                check, IRIS cannot vouch that a staged image is the genuine,
                untampered Cisco release.

        Schedule
        
          
        Cisco's Bulk Hash feed lists the sha512 of every
            genuine Cisco release image. A scheduled or manual check compares
            it against every image in this catalog and quarantines any that
            mismatch, blocking new device assignments until the mismatch is
            resolved or an operator explicitly overrides it.

            feed, outside the schedule above.
